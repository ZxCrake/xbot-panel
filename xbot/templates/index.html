Results

Farm

Autonomous warm-up: the farm keeps your accounts “alive” at a low pace (follows, likes, reads, organic posts) around the clock while they sleep on the server — building a reputation that passes X’s filters.

Control

Runs low-intensity activity (follows, likes, reads, organic posts) drawn from the “Life content” card below — around the clock, at most one action per account per minute, every day. State persists across restarts, and manual tasks are blocked while the farm is running.

Templates

Templates prefill the numbers below — everything stays editable. Slower volumes are safer.

Life content

Large mainstream accounts that are safe to follow. Note: this list is also used as the target list by the Quote Tweet, Follow Target and Send DM actions — update it before running a campaign.

The post ID is the numeric part of the post URL: x.com/<user>/status/<ID>. IDs are used for like, retweet, bookmark and view actions. “Generate” fills the list with recent posts from large accounts.

One post per line. {a|b} variants are picked at random and lightly mutated by the engine. Mentions and links are never sent. Provide 15–30 varied lines.

Photo bank for organic posts: about a third of farm posts attach a random image, like normal user behavior. "Generate" downloads generic stock photos. For best results, curate your own images (uniqueness).

Humanization score

The score is measured from live account data, not estimated. Visibility (40): whether X hides the account’s posts. Growth (20): real followers gained. Depth (20): distinct days with activity. Profile (10): name, bio and photo set. Integrity (10): no authentication failures. A score of 70 or higher is ready for mention/DM campaigns.

Workspace settings

These settings apply to all your tasks.

Rotating residential: lines are reused round-robin across accounts and a unique sticky session is pinned per account (in the proxy username) so each account keeps a single exit IP instead of a new IP per request. One gateway line can therefore serve any number of accounts. Lines that already contain a session marker are used as-is, so provider-specific syntax (e.g. session duration) can be set manually.

Rotating mode only. The session id is appended to the proxy username: -session-… for most providers, ;sessid.… for DataImpulse (detected automatically from the gateway host when set to auto).

Static mode: matched to your accounts by order (account 1 uses line 1, account 2 uses line 2, …); accounts without a line use the fallback below. Rotating mode: lines are reused round-robin for every account, each with its own sticky session. http(s):// and socks5(h):// schemes are supported; HTTP is assumed when omitted.

Shared by accounts that have no dedicated line, and by public content fetches. Leave empty to connect without a proxy.

Rotating gateways only: assigns a fresh sticky session to every account, so the provider serves new exit IPs. Use when the current IPs are flagged by X.
